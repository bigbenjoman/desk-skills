Score each description as the text you would want on this pull request. The ticket above says what
the work was for; this score says whether a reviewer could rely on the description.

### A good description

- Says what was wrong or missing, and what this change does about it.
- Lists the changes that matter to a reviewer, naming the parts of the code they touch.
- Says what was tested, without claiming results it cannot know.
- Fills every section the template asks for, with nothing left as guidance text.
- Is short enough to read in one pass.

### What disqualifies a description (it scores 1)

- It describes a different change from the one the ticket asks for.
- It invents behaviour, data, test results or decisions.
- It is empty, or only restates the headings.

### The points

- **5**: post it as it is.
- **4**: post it after a small edit (a word, a missing detail).
- **3**: the right content, but it needs a real rewrite of one section.
- **2**: it covers part of the change; most of it would be rewritten.
- **1**: disqualified, or no use to a reviewer.
