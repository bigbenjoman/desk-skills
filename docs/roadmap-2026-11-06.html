weeks 3–5Not drafted · changed 9 Nov

Before, this phase moved implementation onto Codex, which would have meant buying ChatGPT Pro 200 (£200 a month). Now the extra capacity is tried on Z.ai Pro, about £60 a month on monthly billing, running GLM‑5.3 inside Claude Code from its own config folder.   • Z.ai as an implementer. GLM‑5.3 runs as a new bench arm on DS-475's frozen tasks first. Then one worker takes well-specified XS–M tickets in desk-skills only. Every one of its PRs goes through the full review, with Claude and Codex seats. Claude Ultra keeps the harder tickets.
  • How it fits rotation. A Z.ai worker is a Claude Code config folder that points at Z.ai, so it can sit in subscriptions.md. Rotation must not hand it any ticket, though: it needs a rule limiting it to the lanes and sizes the bench clears. Z.ai also caps each five hours (12,000 credits on Pro), which Ultra and Pro 200 don't, so it has to be benched at that cap and not only at the weekly one.
  • Codex stays a reviewer. It replaces one Opus review seat, with Claude reviewing anything Codex writes. The codex exec implementer trial (about 20 XS/S tickets) is dropped, and so is buying Pro 200.
  • Fable 5.1 trialled as a Claude implementer, once usage credits are confirmed off on every account (bench arm 3, DS-484).
  • §3b model tiering switched on only for the lanes the eval clears.

Gate: accepted PRs per 10% of weekly allowance, measured on the same frozen tasks and then on live tickets, counting rework. A GLM‑5.3 PR has to pass review as often as an Opus one, with no extra implementation pass. Expect a quality gap: GLM‑5.3 scored 71.5% against Opus 5.5's 87.6% on one independent Terminal-Bench run, and you've seen a 67% vs 87% drop with Sonnet before. If it can't match, it doesn't get live tickets.

Before any live ticket: repo code goes to Z.ai's servers. Start on desk-skills only. Client repos (VoicePA and the others) wait until you've checked Z.ai's data terms against each client's terms.
