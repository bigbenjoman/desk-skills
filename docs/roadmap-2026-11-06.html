  • Same scaffold where possible. Kimi and Z.ai both accept Claude Code's API format, so they run through the bench's existing Claude runner, with only the endpoint and key changed. The comparison then measures the model and not the CLI around it. It also keeps the bench's sandbox, which Kimi's own CLI doesn't have: its -p mode approves every action.
  • What's measured for each run: whether the hidden tests pass, a blind 1–5 quality score, tokens, and how much of the plan's allowance the run used. From those, the report gives £ per accepted task and accepted tasks per 5-hour window. The second figure matters because Kimi, OpenCode, Google and Z.ai all cap each 5 hours, and Ultra doesn't.
  • A concurrency check for each candidate: two tasks at once, recording any queueing, rate-limit errors or failed runs.
  • Your code only. The non-Anthropic arms run on frozen desk-skills tasks only. None of the four confirms in writing that subscription code isn't used for training, and Kimi's and Google's consumer terms allow it. Client repos stay on Claude and Codex.

Gate for each candidate: on the same tasks as Opus, at least as many accepted, a blind score no lower, and a lower £ per accepted task. About 24 tasks only shows big differences, so this is a screen. A candidate that passes then shadows a few live desk-skills tickets, its PRs going through the full review, before it gets a worker. One that fails is cancelled after its first month.
