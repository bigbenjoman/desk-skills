# Adversarial review, 2026-09-27

Five reviewers attacked desk-skills (and pullbot) against real clones of bigbenjoman/voicepa,
pr-ninja, forewatt, yield-index and gygg-platform. This is the deduplicated list of what they found
and how each item is resolved. Evidence and repro scripts were kept in the session scratchpad.

Repo facts that drove the findings (measured, not assumed):
- voicepa: pnpm+turbo; frontend/, portal/ (hard-codes port 3001), backend/ (Python, pytest via turbo);
  hosted Neon DB (no local Postgres); required checks `Verify script sign-off` and
  `Lint, Type Check & Build` (a comma in the name); code-owner review; CLAUDE.md requires
  `./scripts/build-lambda-images-local.sh` before merging backend changes; commits carry
  Co-Authored-By (attribution allowed); `frontend/.env.local` points at the PRODUCTION database.
- pr-ninja: Jira KAN exists but work is named by ids like `BUG-119-5`; main → production promotion
  PRs; protection `strict: true`; files named `claude.md`; Dependabot PRs.
- forewatt: Jira FW (keys in PR titles, never in branches; 22/50 PRs keyless); only `web-test` is
  required, API CI is path-filtered; merge commits; `apps/api/.env` points at PRODUCTION and
  alembic reads it; Python under apps/*.
- yield-index: protected by a RULESET (`main-protected`, requires `CI Passed`), not classic
  protection; Python under apps/*.
- gygg-platform: unprotected; `Lint code` and `Run e2e tests` fail on every recent PR; several DB
  URL variables (`DATABASE_URL`, `GYGG_DATA_DATABASE_URL`, `GYGG_DB_NAME`); `claude.md`.

## Resolved in the foundation commit (desk-env.mjs, desk-config.md)
- List values: one backtick span per item, never split on commas; `|` inside backticks kept.
- Command items may name a directory (`apps/api: uv run pytest`); `desk-env cmds <id>`.
- One definition of "green" (template, Rules section).
- Slugs from any remote form, lower-case; remote-less slug includes a path hash; DESK_GH_REPO
  no longer overrides the repo (DESK_REPO_OVERRIDE, never exported).
- `<slug>` expanded in values. New rows: Other work id patterns, Merge holds.

## Autopilot scripts (desk/bin, clearance-state.mjs)
- W1 P0 worker allow-list: `Bash(git:*)`, `Bash(gh:*)`, the command prefix (`mise`) and the package
  manager wholesale; `git -c alias.p=push`, `!` aliases, `gh alias`, `gh api graphql`, `npm x`,
  `pnpm exec`, `mise exec -- gh pr merge`, `with-lock.sh`/`flock` wrapping all bypass the denies.
  On an unprotected repo a worker can push to main or merge its own PR.
- W2 P1 worker settings path `$DESK_HOME/workers/$TICKET.settings.json` is not per repo.
- W3 P1 setup-worktree copies the human's `.claude/settings.local.json` (with merge-driver allow)
  into worker worktrees.
- W4 P0 pass.mjs spawns into worktrees whose setup failed (checks only existsSync); a re-run of
  setup-worktree says "already exists" and exits 0.
- W5 P0/P1 database: rewrites a HOSTED URL as if local; only the first env file; only one variable;
  prints `database=<name>` after create failed; with Local database `none` the worker keeps the
  production URL; `db-migrate-cmd` is allow-listed even without a per-ticket DB.
- W6 P0 merge-driver merges past review feedback when merge-feedback-first is unset/ask
  (clearance treats unset as strict) — use perm-or-unset.
- W7 P1 merge-driver gate: every-check-skipped passes; an early passing check before CI queues
  passes; skipped required check passes; no --match-head-commit; required checks split on commas.
- W8 P1 merge-driver PR selection: no base-branch filter (picks main → production promotion PRs);
  `BUG-119` matches `BUG-119-5`; slug keys never match `<type>/<slug>-<suffix>` branches; retries
  one refused PR forever (stalls the batch); never updates a behind branch (strict protection).
- W9 P1 merge holds: nothing stops autopilot merging a PR that needs a manual pre-merge step.
- W10 P1 tracker none / other work ids: triage.sh and merge-driver.sh accept only lowercase slugs;
  planning ids (`P1-M14-FIX-1`, `BUG-119-5`) are refused; the ticket file the orchestrator must
  write is undocumented.
- W11 P1 answer.mjs un-parks a ticket, so a lane C/D ticket runs unattended.
- W12 P1 workers are told to run `desk-env` but only `desk-env.mjs` is allowed.
- W13 P1 workers can Write anywhere in the batch state dir (fake `answers/`, locks, cooldowns).
- W14 P1 with-lock.sh breaks on `cd dir && …`; needs `--cwd`.
- W15 P2 queue concurrency and the spawn gate ignore §3b; plan-batch claims a DB is provisioned
  when Local database is none; `desk-env heavy` misses Python processes; the preflight probe only
  proves the first toolchain; bare `python` never allowed; `--maxWorkers` appended to pytest;
  clearance-state exits 1 with zero open PRs; gate disagreement with clearance on skipped checks;
  merge-driver reruns chronically red checks forever.

## Hook, desk-jira, harness rules, installer
- H1 P1 attribution hook decides by the session cwd, not the repo each subcommand targets
  (`cd other && git commit`, `git -C other commit`).
- H2 P1 hook misses `git merge -m`, `git tag -m`, `git commit-tree -m`, `gh issue comment`,
  `gh release create --notes`, `bash -c`/`sh -c`/`eval`, and a `-F file` written earlier in the same
  command; docstring overclaims "any author".
- H3 P1 desk-jira puts `email:token` on curl's argv (visible in ps) — use `curl -K -`.
- H4 P1 desk-jira posts any readable file as a comment/body (another repo's token).
- H5 P1 desk-jira search reports "no issues" with exit 0 on a bad token.
- H6 P2 desk-jira derives the slug itself (trailing slash disagreement, DESK_SLUG leak) — use desk-env.
- H7 P2 harness-rules.py writes allow rules to ~/.claude/settings.json when no --settings is given;
  must refuse user-level allows and a settings.local.json git does not ignore; remove on a
  never-existing file claims it removed something.
- H8 P2 installer copies __pycache__; warns about flock on macOS though a fallback exists.
